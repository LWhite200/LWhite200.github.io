Load-Balanced Client-Server Sales System

A multi-threaded client-server application built for a class project, designed to handle over a thousand concurrent transactions using load balancing across server threads.

Java SQLite Multi-threading Network Programming Load Balancing JavaFX
View on GitHub

Overview

This project grew out of a class assignment on distributed systems, but I pushed it further than the assignment asked for. I built a multi-threaded client-server application that can support over 1,000 concurrent transactions, handling real-time network communication, error handling, and data serialization between clients and the server.

How It Works

Incoming requests get distributed across multiple service threads rather than handled one at a time, which is what lets the system stay responsive under heavy concurrent load. The architecture is built to scale horizontally, and I built in redundancy strategies to handle failure cases gracefully instead of letting one bad connection take down the system.

On the data side, SQLite handles storage for sales records, with SQL queries written to keep everything accurate and consistent even with many transactions happening at once. A JavaFX GUI sits on top for product entry, receipt generation, and sales tracking, so the whole thing is usable end to end rather than just a backend exercise.

Key responsibility: Designing the load balancing and redundancy logic that keeps the system reliable under heavy concurrent traffic, then proving it out with simulated load testing.

Key Contributions

  • Implemented request distribution logic across multiple server threads.
  • Designed a scalable architecture that supports horizontal expansion.
  • Built redundancy strategies to handle failure cases without taking down the whole system.
  • Tuned system performance to hold up under heavy simulated load.
  • Tested behavior under simulated traffic to validate the load balancing approach before calling it done.

What I Learned

This was my first real dive into distributed systems concepts outside of a textbook — actually building load balancing and redundancy logic instead of just reading about it. It gave me a much better sense of what "scalable" really requires in practice, and how much of reliability comes down to planning for failure cases up front instead of patching them in later.
