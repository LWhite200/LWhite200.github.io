3D Island — Wii Homebrew

A personal project to build a real-time, procedurally generated 3D island world for the Nintendo Wii — written entirely in C with no game engine, just low-level graphics programming.

C DevKitPro GRRLIB GX / GCCORE Low-Level Graphics Procedural Generation
View on GitHub

Overview

This was a personal project to see how far I could push the Wii's hardware without leaning on a game engine. I built a real-time 3D island generation engine from scratch in C, using DevKitPro and GX directly — meaning every part of the rendering pipeline, from the graphics to the physics, is something I wrote myself rather than something an engine handed to me.

The world is semi-infinite and procedurally generated, made up of ocean and island terrain that's created on the fly as the player explores, rather than loaded from fixed level data.

Key Contributions

  • Built a procedural terrain generation system for semi-infinite ocean and island environments.
  • Wrote a custom rendering pipeline directly against the Wii's GX graphics library.
  • Built the physics system governing player and boat movement, including collision handling.
  • Designed a dynamic camera system that tracks the player smoothly through the generated world.
  • Profiled and optimized the rendering and simulation loops to stay within the Wii's tight memory and CPU limits.
Technical highlight: Real-time collision detection and kd-tree spatial queries keep the world responsive while terrain is generated and despawned on the fly — a big part of making a "semi-infinite" world feel seamless on hardware this constrained.

What I Learned

Working this close to the hardware, with no engine to fall back on, forced me to actually understand what a game engine normally does for you — rendering, physics, memory management, all of it. It's the project that pushed my low-level C and graphics programming the furthest, and gave me a real appreciation for performance constraints most modern development doesn't force you to think about.
